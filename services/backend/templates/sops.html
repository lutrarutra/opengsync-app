Steps:
  1. Open the pool page of the pool you want to re-sequence.
  2. Click the "Clone Pool"-button on top right.
  3. Give the new pool a name, e.g. add suffix '_re' (the name is not changed automatically), and fill other fields as required. -> complete
Notes:
  • The libraries associated with the original pool will be cloned to the new pool with their samples and indices. Cloned libraries get status {{ C.LibraryStatus.POOLED.display_name }}; the original pool and its libraries are not changed.
  • Each cloned library will retain its original sequencing request.
  • The new pool copies the original pool's contact, BA report, fragment size, qubit concentration and dilutions. It is not added to any experiment.
  • The pool type cannot be changed; the contact is always copied from the original pool.
  • Re-Sequenced Pools and Libraries will be marked with '(re: X)' where X is the clone number: the number of existing clones of the original pool/library + 1. Cloning a clone counts towards the same original.

Steps:
  1. Manual
    1. Open the sequencing request page containing the library you want to re-sequence.
    2. Go to 'Libraries'-tab.
    3. Find the library you want to re-sequence and click the "Re-Sequence Library"-button in the context menu (right-click on library name).
    4. The clone keeps the indices of the library and gets status {{ C.LibraryStatus.PREPARING.display_name }}.
  2. Workflow
    1. Open the sequencing request page containing the library you want to re-sequence.
    2. Go to 'Workflows'-tab.
    3. Start the 'Re-Sequence Libraries' -workflow.
    4. Select the library/libraries you want to re-sequence from the list.
    5. In 'Options'-tab, choose the 'Re-Sequencing Type':
      • Indexed: indices are copied, clones get status {{ C.LibraryStatus.STORED.display_name }}.
      • Raw: indices are not copied, clones get status {{ C.LibraryStatus.ACCEPTED.display_name }} (library is prepared again).
    6. Click 'Re-Sequence'.
Notes:
  • The re-sequenced library will be cloned to the same sequencing request.
  • The cloned library will not be associated with any pool. You need to add it to a pool manually.
  • The 'Re-Sequence Libraries' -workflow is not available for QC-only requests.
  • Re-Sequenced Libraries will be marked with '(re: X)' where X is the clone number: the number of existing clones of the original library + 1. Cloning a clone counts towards the same original.

Steps:
  1. Open 'Pools'-page.
  2. Click "New Pool"-button on top right.
  3. Fill in the pool details -> complete; you are redirected to the new pool's page.
  4. Go to 'Workflows'-tab.
  5. Click "Add Libraries"-button and select the prepared library from the list.
Notes:
  • Only libraries that are not yet pooled are listed.
  • 'Add Libraries' only assigns the libraries to the pool; library status and request status are not changed.
  • If the libraries are part of a lab prep, prefer the 'Pool Libraries'-step in the lab prep checklist: it sets the libraries to {{ C.LibraryStatus.POOLED.display_name }} and updates the request status.

Steps:
  1. Start the 'Re-Index Libraries' -workflow from the 'Workflows'-tab of the dashboard, the pool page or the sequencing request page (in a lab prep checklist it is the 'Index Libraries'-step).
  2. Select the library you want to remove the index from
  3. Write del in the 'Index Well' -column
  4. Complete the workflow
Notes:
  • del must be lowercase.
  • An empty row without del is not accepted; it does not remove the index.

Steps:
  1. In prep_table (Excel sheet), add column plate.
  2. Assign each sample to a plate, e.g. plate_1, plate_2, etc.
Notes:
  • Each plate_well must be unique for the same plate.
  • plate_well is required for every library and must be between A1 and H12. Use one well format consistently (e.g. A1, not A01).
  • The downloaded prep_table only pre-fills wells for the first 96 libraries; fill in the rest manually.
  • A plate is created for each distinct plate value; libraries without a plate go to the default plate.
  • Uploading the prep_table again replaces all plates of the lab prep.

Steps:
  1. On dashboard (or sequencing request page) 'Workflows'-tab, select workflow 'Edit Libraries'
  2. Select libraries you want to modify
  3. Modify as required.
Notes:
  • Editable: sample name, library name, library type, genome, assay/service type, nuclei isolation, protocol.
  • Changing the library type also renames the library: the type suffix of the name is replaced, e.g. S1_GEX -> S1_ATAC.
  • The 'Edit Library'-form on the library page always sets the name to <sample name>_<library type> on save, even if only other fields are changed.
  • ⚠️ If the library is already sequenced and demultiplexed, do not change its name, sample name or library type (this would rename it).
  • To change library properties (e.g. Visium metadata), use the 'Properties'-button instead (see below).

Steps:
  1. ⚠️ Applies to raw sample submissions only!
  2. For each project, complete 'Add Samples to the Request' -step separately.
  3. If projects are billed separately, create separate sequencing requests for each project.
  4. During library-prep, begin the 'Specify how Samples are Pooled'-step.
  5. Put samples from different projects into the same library by specifying same name in 'Pool'-column.
Notes:
  • ⚠️ Consider potential issues with data privacy; reads from different projects will be combined in the same library. To separate raw reads per project, custom demultiplexing needs to be performed.
  • ⚠️ A library belongs to a single sequencing request. If samples from different requests are pooled into the same library, the library is assigned to only one of the requests, and libraries of the other request that are left without samples are deleted.
  • The step is only available when the lab prep contains multiplexed libraries and is not completed.
  • Only samples with the same library type are combined; each Pool/library-type combination becomes one library named <Pool>_<library type>.
  • Every sample must be assigned a Pool. A sample that is in several libraries with different barcodes cannot be moved to a new pool.

Steps:
  1. Open the lab prep page -> 'Checklist'-tab.
  2. Begin the 'Reject Samples'-step.
  3. Specify x in the 'Reject'-column for the failed samples -> submit.
  4. Continue with the remaining checklist steps; rejected samples are ignored in checklist checks, sample multiplexing (Flex, OCM, ...) and the prep-table sheets.
Notes:
  • The 'Reject Samples'-step is only available when the lab prep contains multiplexed libraries and is not completed.
  • Rejected samples get status {{ C.SampleStatus.REJECTED.display_name }} and stay in their library.
  • Rejected samples are still listed (marked with {{ C.SampleStatus.REJECTED.icon }}) in the 'Specify how Samples are Pooled'-step. Leave them in their current Pool.
  • To undo, clear the x in the 'Reject Samples'-step; the sample status is set back to {{ C.SampleStatus.STORED.display_name }}, regardless of its status before rejection.
  • If all samples of a library are rejected, fail the library with x as the Pool in the prep-table.
  • Rejection applies to the sample everywhere it is used. The customer cannot re-use the name of a rejected sample within the same project and has to submit it with a different name.
  • Only insiders can edit a rejected sample.

Steps:
  1. Open sequencing request containing the library.
  2. In libraries-tab, click 'Properties'-button.
  3. To add a column, right-click a column header, select "Insert a new column before/after" and enter its name. To rename a column, right-click its header and select "Rename this column".
  4. Edit as required columns image, slide, area, and optionally he_image (H&E image).
Notes:
  • Requestors can edit while the request is a draft; after submission, only insiders can edit.
  • Column names are saved in lowercase with spaces replaced by _. Removing a column removes that property from the libraries.
  • Properties of a single library can also be edited on the library page ('Edit Properties').

Steps:
  1. 'Merge Projects' -workflow.
Notes:
  • This workflow is meant to be used to merge a draft or a submitted project into existing one, in case the customer (or we) forgot to do so.
  • Samples of the source project are moved to the destination project. Samples with the same name are merged; differing attribute values block the merge.
  • Avoid selecting project that is already sequenced as the source project. This is not blocked: the source project is left empty (not deleted), its data paths stay with it, and the destination project's status is not updated.
  • More information can be found in the 'Merge Projects' workflow.
  • Only insiders can merge projects.

Steps:
  1. Create a single sequencing request.
  2. For each project, complete 'Add Samples to the Request' -step separately (run the workflow once per project).
  3. Complete 'Upload Signed Sequencing Authorization Form' -step.
  4. Complete 'Submit Sequencing Request for Review' -step.
Notes:
  • ⚠️ Only for projects of the same entity (e.g. the same lab). Projects of different organizations/entities must be submitted in separate sequencing requests.
  • The request will be billed in a single bill. If you want separate billing, create separate sequencing requests for each project.
  • The data for each project will be delivered separately, to recipients chosen from the request's 'Share'-tab.
